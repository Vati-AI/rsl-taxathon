TAX-022 provides typed investigation state, case-scoped tool result envelopes, and a deterministic fake-tool LangGraph. It makes no live service calls and performs no tax assessment or enforcement action.

For the model-free graph, construct state with `create_investigation_state(...)` and invoke `build_fake_tool_graph()`. The state factory requires tenant, case and run IDs and limits each run to at most eight tool calls. Tool failures are returned in the error envelope and stop execution for human review.

TAX-048 adds `ai/tools/refund_reconciliation.py` (Decimal-only claimed/explained/unresolved refund reconciliation over synthetic records) and `ai/workflows/refund_lanes.py` (a case-scoped tool plus `reconcile -> propose_lane` nodes). The fast/standard/targeted lane is an advisory proposal with `decision: null` that always requires officer approval; thresholds are prototype choices documented in the module, not RSL policy.

TAX-050 adds `ai/tools/imported_services.py` and `ai/workflows/imported_services_playbook.py`. Charges marked as imported services (explicit `supplier_residence: "non_resident"` or the TAX-024 `vat_status: "treatment_unverified"` marker; never inferred from names) are traced contract -> invoice -> payment (+ declared withholding) -> declared VAT/withholding treatment with Decimal amounts. Missing records become gaps, contradictory records discrepancies, and each gap drafts a neutral, evidence-linked question for officer approval. Statutory treatment is always `unverified_pending_expert_review`; the advisory finding (`code: imported_service_treatment_unverified`) is compatible with the TAX-052 policy-gap gate, which reports the legal route separately and blocks enforcement conclusions.

TAX-047 adds `ai/workflows/human_checkpoints.py` (ADR-014). Runs persist in a SQLite checkpoint file you pass explicitly (`open_checkpointer(path)`) and interrupt before any consequential action. `resume_with_approval` continues only for the authenticated supervisor who approved the matching TAX-046 decision, bound to tenant, case, draft, case version and the SHA-256 of the exact action payload; refusals leave the run paused. Approved actions go through an injected idempotent `ApprovedActionPort`, so `recover_run` after a worker crash cannot apply an action twice. The worker never calls Jube or Frappe directly.

TAX-051 adds `ai/tools/work_arrangement.py` and `ai/workflows/work_arrangement_playbook.py`. Cited contract, work-evidence and statement facts are grouped by a neutral factor checklist (not a weighted legal test) and marked unknown, consistent or conflicting; the payment pattern is derived from invoices. A contract with an `unresolved` classification or conflicting facts is referred: the run persists the structured facts in the TAX-047 SQLite checkpoint and pauses. Only an authenticated specialist (TAX-046 `specialist.opinion.record`), bound to tenant, case, case version and the SHA-256 of the facts reviewed, can resume and record an attributed opinion; the agent never classifies or assesses, and an officer decision is still required.
