# ADR-021: Cited case briefing with validated references and fenced evidence text

Status: proposed (TAX-053, pending review); the "no hosted model" alternative is superseded for synthetic data by ADR-031, and the validation rules below apply to every model
Owner and task: Leseli (owner, handed over by Gupta), TAX-053; implemented by leseli-claude-20261105-053. Review: Gupta (AI area), Edga for the evidence-read rule.
Date: 2026-11-05

Context and smallest prototype need: TAX-053 needs evidence search and an officer briefing with the sections what happened, what was checked, what is explained, what is unresolved and next action, where every statement has source references. Citation IDs must exist, source permissions must hold, and prompt injection in documents or tool output must have no effect. AI_STANDARD treats document text and retrieved results as untrusted data, requires a resolvable evidence locator or an explicit marker for every reported claim, and says missing evidence yields a gap, not an invented citation or conclusion. Evidence records and their extraction items with page and record locators exist from TAX-032 and TAX-038. The tool interface (TAX-022) and SQLite checkpoints (TAX-047) are in place. No hosted model provider is approved for this project yet.

Decision:

- **Search (`ai/tools/evidence_search.py`).** Pure functions. The caller must be authenticated, a member of the tenant and hold a role allowed `evidence.read`. `EVIDENCE_READ_ROLES` mirrors `vati_tax.identity.policy.ACTION_ROLES["evidence.read"]`, and a test keeps them equal. The check happens before any document is read. Only documents of the requested tenant and case are searched; superseded versions are skipped, and documents whose extraction isn't `completed` are reported as unsearchable. Only items with a page or record locator can be cited. Each hit gets a citation ID `<evidence_id>#<item_id>` and carries the contract `EvidenceRef` fields. Questions are validated (ID, topic, lower-case word terms) and bounded (12 questions, 8 terms, 5 hits each, 500 documents).
- **Briefing (`ai/workflows/case_briefing.py`).** The graph is `search_evidence -> draft_briefing` on `InvestigationState`. A `BriefingModel` port drafts from a request in which document text appears only in an `untrusted_evidence` block next to fixed instructions (`PROMPT_VERSION`). The default `DeterministicBriefingModel` is template-based: it never quotes free text, only short plain values such as amounts and IDs, and it reports instruction-like items as unresolved untrusted content.
- **Validation.** Every draft is validated, whatever model produced it. Each statement needs at least one reference that resolves to this run: an evidence citation the permitted search found (expanded to an `EvidenceRef`), a search the run performed, or an in-scope document. Fact and explanation sections must cite evidence. Missing information may cite only searches that found nothing and may not be worded as a discrepancy. Statements with assessments, refund decisions, accusations, penalties or legal conclusions, or with instruction-like text, are rejected. Next actions are limited to `request_evidence`, `human_clearance` and `specialist_review`, and always require officer approval. Rejected statements are kept with a reason code.
- **Tool output is untrusted.** Search results whose tenant, case or hit documents don't match the run stop it with `tool_scope_mismatch`. The tool's own labels are not trusted either. `build_briefing_graph` takes an `evidence_source` and re-reads the active tenant and case's documents from it independently of the tool. Every listed document and every hit must exist there with the same document SHA-256, or the run stops with `tool_scope_mismatch`. If the store can't be read, the run stops with `evidence_verification_failed` (TAX-056 finding F4: a fully relabelled result from another case had passed the label check).
- **Record.** The briefing is recorded once per run as a `case_briefing` finding with the model ID and configuration, prompt version, searches, cited evidence IDs, a search digest and `decision`/`legal_conclusion`/`enforcement_conclusion` set to null. A re-executed draft node keeps the existing briefing, so checkpointed runs don't redraft.

Alternatives and tradeoff: Calling a hosted model now was rejected: no provider is approved, runs wouldn't be reproducible and no evaluation exists yet (TAX-056). The port allows one to be added later, behind the same validation. Free-text summaries quoting documents were rejected because quoted text can carry injected instructions or accusations; templated statements are less fluent but safe. Detecting injection and then refusing the whole run was rejected: detection is a heuristic that only flags text for an officer, and safety comes from structure (fixed scope, fenced text, validated output) rather than from catching every phrasing.

Official sources and version/date checked (2026-11-05): docs/AI_STANDARD.md, AGENTS.md, ADR-001, ADR-007 (`evidence.read` roles), ADR-011 and ADR-014 in this repository; `integration/api/openapi.json` `EvidenceRef`, `EvidenceLocator` and `ProposedAction`; LangGraph 1.2.19 and langgraph-checkpoint-sqlite 3.1.2 as locked in `ai/requirements.lock`.

Verification performed: `tests/ai/test_case_briefing_search.py` (13 tests, no LangGraph) and `tests/ai/test_case_briefing.py` (14 tests, LangGraph 1.2.19 in a local venv built from `ai/requirements.lock`) all pass. They cover all five TAX-024 scenarios fully cited with no conclusions; rejection of invented, cross-tenant and misplaced references; missing information never reported as a discrepancy; rejected conclusions and actions that aren't allowlisted; injected document text that is flagged and changes no scope, question or action; a model that obeys injected text being contained; poisoned tool output stopping the run; refusal before any document is read for taxpayers, other tenants and unauthenticated callers; the step budget; and a checkpointed replay that doesn't redraft. mypy (repository config, plus the new modules against the locked LangGraph) and ruff pass.

Consequences and revisit trigger: TAX-054 can call the briefing graph after the pipeline steps and pass playbook gaps as questions. TAX-056 should add adversarial injection and stochastic-model runs through the same port, with three runs per scenario. Exposing briefings through the Vati API needs a contract change and review. Revisit when a hosted model is approved: record its ID and settings per run, keep the validator, and rerun the five-scenario evaluation. Also revisit if officers need free-text quotes, which would need an explicit quoting mode that keeps text fenced.
